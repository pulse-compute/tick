# TICK-07 S3 conditional-write candidate

TICK-09 uses shared data-only record capture; root/run serialization hooks cannot rewrite
claims. Partial/expiring NoSuchKey errors grant neither absence nor a known conflict.

`@pulse-compute/tick/adapters/s3` exports `createS3Store(options)` and `S3Options`.
The `s3-http` [logical mapping](bindings.md) resolves the same adapter. This is an
experimental coordination candidate; the [deployed proof](../proof/s3/README.md) is
implemented but its live gate remains **INCONCLUSIVE**.

```ts
import { createS3Store } from '@pulse-compute/tick/adapters/s3';
const store = createS3Store({
  endpoint: 'https://scheduler-state.s3.us-east-1.amazonaws.com',
  fetch: signedTransport,
});
```

The host supplies an authorized transport closure. It signs each exact operation with
AWS SigV4, including the condition headers and payload hash, and sends it **once**.
It must preserve encoded paths, method, body, headers, and the optional native signal;
disable caching, redirect following, and SDK/network retries. A retry after a lost
successful response can return 412 and conceal a commit; such transports do not satisfy
this binding. Fastly uses a fixed backend with cache override `pass`, explicit Host/TLS
configuration, and verified timeouts. Cooperative Tick signals are not fetch signals.
The [proof-only WebCrypto recipe](../proof/s3/sigv4.mjs) signs bounded single-chunk GET/PUT
and supports explicit temporary session credentials. It is tested against public AWS
signature vectors and the actual guest fixture; it is not a published signing SDK.

Construction validates/captures endpoint, transport and optional native signal without
opening resources or loading credentials. The endpoint is a HTTPS bucket **origin**,
without credentials, path, query or fragment. The initial recipe targets regional,
virtual-hosted AWS general purpose buckets. No endpoint/region/credential discovery,
path-style buckets, directory buckets, access points, Outposts, multipart operations,
or version selection is supplied. An S3-compatible endpoint needs its own deployed
conformance evidence; accepting a URL does not certify its conditional semantics.

## Wire contract

| Operation/response | Tick result |
| --- | --- |
| GET 200, full valid contract record and one strong quoted ETag from that response | `found`, preserving ETag byte for byte |
| GET 404 with bounded standard S3 `NoSuchKey` envelope | `absent` |
| GET bucket/auth/region/proxy errors, malformed data, weak/missing ETag, partial or expiring object, delete marker | `unavailable` |
| PUT `If-None-Match: *` | Atomic create if no current object |
| PUT `If-Match: <exact ETag>` | Atomic replacement against the observed current object |
| PUT 200 | `applied` |
| PUT 412; or revision PUT 404 with verified `NoSuchKey` | `conflict` |
| Lost reply, 409, redirect, auth/throttle/server error, other 2xx, unverified 404 | `indeterminate` |

Each operation makes at most one transport call. There are no HEAD/read-before-write
requests, automatic retries, unconditional PUTs, TTL, deletes, or background work.
Invalid writes throw sanitized `TypeError` before I/O. Values and the exact serialized
JSON must satisfy contract v1, bounded to 16 KiB; keys are at most 1,024 UTF-8 bytes.
Full keys receive no extra prefix. Slashes/empty segments remain literal; all reserved
bytes are encoded once. Dot/dot-dot segments, control bytes and invalid Unicode reject
because URL normalization would otherwise change the selected object.

ETags are equality-only opaque **quoted strings**, not version IDs, MD5 calculations,
numeric generations or downstream fencing tokens. Weak tags, lists and wildcards
cannot be replacement preconditions. S3 ETags can repeat for identical content;
every distinct Tick transition must retain its globally unique mutation ID. Never
restore previous bytes, reset records, or reuse mutation IDs. Header syntax checks
do not establish collision resistance or provider semantics.

## Bucket and authority requirements

All writers must address one regional bucket/current-key domain, with no caching proxy
or replica reads. Grant `s3:GetObject`/`s3:PutObject` on the isolated prefix and scoped
`s3:ListBucket` for observable missing keys (otherwise a missing read may return 403).
Use bucket policies to enforce conditional writes and prevent other principals from
unconditionally overwriting/copying or deleting retained objects. Disable expiration,
archive transitions, replication destinations writing this prefix, and restoration of
old versions. Versioning alone does not retain the current logical highwater mark:
a current delete marker permits a new conditional create. The adapter detects visible
delete markers/expiration on reads but cannot police bucket lifecycle or external writers.
Object Lock is not an ownership primitive and can obstruct required replacements.
Encryption/key policies and any additional signed headers remain host responsibilities.

An indeterminate write never grants ownership. The core reconciles the exact mutation,
then requires a positive conditional revalidation with usable time. Stale owner ETags
must reject after a successor's mutation. These conditions do not compare server time,
prevent physical overlap, authorize external effects, or supply exactly-once execution.
S3 request latency and Fastly invocation/backend budgets must be measured before use.
